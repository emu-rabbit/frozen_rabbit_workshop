# 產品架構：備料、待辦與推薦筆記

## 概述
`frozen_rabbit_workshop` 的心智模型是「把製作目標變成可執行的備料計畫」。後續 Agent 在設計資訊架構、命名、UI 文案、路由、元件或資料流程時，必須先用本文件理解專案分工。

## 主要系統

### 推薦筆記 (Recommended Notes)
- 站長整理的精選清單，位於 `src/data/recommended/`。
- `name` 可為字串或 `{ tw, cn, en, ja }` 多語物件；已完成多語物件不可在 `/process-recommended` 中被任意改寫。
- 使用者可以收藏、搜尋並載入備料台。
- 推薦筆記是「精選清單」，不是絕對最佳配裝或唯一備料路線。

### 備料台 (Workbench)
- 核心工作區，負責展開素材需求並讓玩家分配購買、製作、採集或其他來源。
- 重要檔案包含 `src/components/views/WorkbenchView.vue`、`src/composables/useWorkbench.ts`、`src/services/dictionary.ts`、`src/services/gathering.ts`、`src/services/universalis.ts`。
- 分配數量必須能清楚顯示未分配或超分配狀態。
- 市場價格、製作條件、採集地點與 NPC 資訊應優先服務快速判斷。

### 待辦清單 (Todo List)
- 由備料台決策生成行動清單。
- 目標是讓玩家知道要買什麼、採什麼、做什麼，以及要去哪裡。
- 如果備料台資料不完整，待辦清單應呈現限制或缺漏，不應安靜吞掉。

### 歷史、收藏與設定
- 歷史與草稿保存玩家自己的筆記與工作狀態。
- 收藏偏好應保持輕量，不要把收藏功能變成複雜的求解器狀態。
- 設定包含語言、主題、資料中心、市場策略與 analytics consent 等行為。

### FAQ 與 Changelog
- FAQ 是玩家面向的說明，語氣要自然、簡潔，避免內部除錯用語。
- Changelog 是版本可見面，新增使用者可感知功能或修正時應同步更新。

## 命名與文案邊界
- 對外文案優先使用「備料」、「估算」、「建議」、「推薦筆記」、「市場策略」。
- 避免宣稱「最佳」、「最優」、「保證最低價」、「絕對省錢」。
- 程式內 legacy 命名若已存在，不必為文字潔癖大規模重構；新增使用者可見文案應採保守且清楚的語氣。

## 產品對外 UI 與 Locale 規範
- 產品可見 UI、FAQ、changelog、README 與 locale 內容由本 mission skill 與對應 business skill 管理，不由 `core/language_policy.md` 管理。
- 新增或修正使用者可見 UI 字串時，預設同步檢查 `tw`、`cn`、`en`、`ja`。
- 若只修改單一 locale，必須是使用者明確要求、或該文字只存在於特定語系內容中。
- 同一概念在不同頁面與 locale 中應維持一致，例如市場策略、推薦筆記、備料台、待辦清單、資料中心、HQ/NQ 與價格估算。
- `tw` 應使用自然繁體中文；`cn` 使用簡體中文；`en` 與 `ja` 應是自然的產品文案，不要殘留中文或內部 debug 詞。
- UI 文案要符合玩家實際看到的流程，避免暴露內部實作標籤或只對開發者有意義的術語。

## 功能歸屬判斷
- 站長預先整理的清單：放在推薦筆記。
- 玩家正在分配素材來源：放在備料台。
- 玩家要照著做的行動項：放在待辦清單。
- 玩家偏好、資料中心與市場策略：放在設定。
- 跨頁持久化資料：優先走既有 composable，不要讓單一 component 私自擁有全域狀態。
