# 全域行為規範 (Global Standards)

## 概述
本技能定義 Agent 在 Frozen Rabbit Workshop 中的基礎工作方式：先理解真實專案脈絡，再以可驗證、可維護、變更聚焦的方式完成任務。

## 觸發條件
- 接收到任何新的使用者請求時。
- 需要做出產品、資料、實作或測試決策時。
- 準備產出長篇回覆、計畫或文件時。

## 核心規則

### 分析行為
- **先查再判斷**：優先讀取實際程式、workflow、locale、測試或資料檔，不只依記憶或命名推論。
- **任務拆解**：將複雜問題拆成可驗證的小步驟。
- **透明假設**：若存在不確定前提，必須明確說出假設條件。
- **避免過度設計**：優先選擇簡單、穩定、符合既有架構的解法。
- **誠實面對不確定性**：遇到資料來源、遊戲公式、API 行為或使用者意圖不明時，不可臆測成事實。

### 回應風格
- **繁體中文優先**：依 `language_policy.md` 回覆。
- **直擊重點**：先講結論與已完成事項，再補必要細節。
- **用事實支撐**：涉及 CI、部署、資料來源、價格策略或 UI 行為時，盡量指向實際檔案或驗證結果。
- **保守措辭**：市場價格、成本、時間與推薦清單都會受資料與情境影響；對外避免過度承諾。

## 檔案編碼規範
- **UTF-8 優先**：所有 `.agents`、Markdown、locale 與資料檔應以 UTF-8 儲存。
- **Windows 讀檔安全**：在 PowerShell 中讀取 `.agents`、skill、workflow 或中文 Markdown 時，使用 `Get-Content -Encoding UTF8 <path>`。
- **搜尋與編輯工具**：搜尋優先使用 `rg`；手動修改檔案時優先使用 `apply_patch`。
- **損壞復原**：若讀取結果出現亂碼，先用 UTF-8 重新讀取；若檔案真的已損壞，先回報並確認復原範圍，不可擅自還原使用者或其他 Agent 的變更。

## 驗證規範
- 修改程式碼後，依影響範圍執行最小但足夠的驗證。
- 修改 locale 或推薦筆記時，優先跑相關 unit test；若測試不存在，至少用 `rg` 和 TypeScript/build 檢查引用。
- 修改前端樣式、暗黑模式或互動流程時，盡量用 build 與瀏覽器或截圖驗證真實畫面。
- 若無法執行測試，需在回報中明確說明原因與剩餘風險。
