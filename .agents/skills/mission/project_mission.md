# 專案使命與核心目標

## 1. 專案定位
本專案 **Frozen Rabbit Workshop** 是 Final Fantasy XIV (FFXIV) 的能工巧匠與採集素材備料管理工具。

它的核心任務是協助玩家把大型製作目標拆解成清楚的素材需求，並依照個人決策分配為：

- 購買
- 製作
- 採集
- 既有庫存或其他來源

接著再把這些決策轉成可執行的待辦清單、成本估算與時間估算。

## 2. 核心痛點與解決方案

- **痛點**：大型裝備、消耗品與版本初期備料常牽涉大量中間素材、不同職業、採集點、NPC、HQ/NQ 價格與市場波動，人腦很難快速整理成可執行清單。
- **解決方案**：透過 Teamcraft 資料拆配方與採集資訊，透過 Universalis 估算市場成本，再由 UI 讓玩家自行決定每個素材的取得方式。

## 3. 三大設計準則

### 資料正確性
- Teamcraft、Universalis、XIVAPI 與本地 JSON 的資料路徑必須可追蹤。
- 物品 ID 應以 Teamcraft `data.itemId` 或已確認的 canonical ID 為準，不可用壓縮搜尋索引中的暫時 ID 取代真實 item ID。
- 若資料來源不一致，應先追蹤來源與轉換流程，不要用 UI 補丁掩蓋資料模型問題。

### 操作效率
- Workshop 是日常備料工具，主線流程應保持快速：選筆記或建立清單 -> 分配來源 -> 生成待辦。
- UI 應方便掃描大量素材，避免為了裝飾犧牲資訊密度。
- 特殊功能可以存在，但不應阻擋普通玩家完成備料。

### 舒適與可信任
- 四語系、暗黑模式、RWD 與可存取性都屬於功能品質的一部分。
- 產品對外可見 UI 預設維持繁體中文 (`tw`)、簡體中文 (`cn`)、英文 (`en`) 與日文 (`ja`) 四語同步；新增或修正可見文字時，除非使用者明確指定單語，否則應檢查四語 parity。
- 市場價格與時間估算應明確呈現為估算，不要宣稱絕對最低或保證正確。
- API 失敗、資料缺漏、無市場價格或不可購買素材都應以可理解方式呈現。

## 4. 決策邊界
當任務涉及以下情況時，應主動停下來釐清或向使用者確認：

1. 遊戲資料或 API 結構疑似改版。
2. 同一物品出現多來源、多職業或 ID 對不上。
3. UI 改動會影響備料台或待辦清單的快速操作路徑。
4. 新功能可能破壞四語系、暗黑模式或手機版佈局。
5. 需要把「推薦」、「估算」改寫成更絕對的宣稱。
