# 繁體中文溝通與文件規範技能

## 概述
本技能確保 Agent 在與使用者互動、撰寫計畫、記錄進度以及產出任何專案文件時，皆保持一致的繁體中文語系，以符合使用者偏好與本專案既有文件風格。

## 觸發條件
- 任何時候 Agent 需要對使用者做出回應。
- 建立或更新 `.agents`、README、FAQ、changelog、工作紀錄或其他 Markdown 文件。
- 撰寫程式碼註解、測試名稱或使用者可見文案。

## 核心規則
- **語系優先**：所有輸出必須以繁體中文為主。
- **保留詞彙**：技術關鍵字、程式碼識別字、套件名稱、API 名稱與無通用中文譯名的專有名詞可保留英文。
- **四語同步**：新增或修正使用者可見文字時，預設同步檢查 `tw`、`cn`、`en`、`ja`。
- **一致性**：同一概念在不同文件、locale 與 UI 中的譯名應保持一致。
- **避免簡體滲漏**：除 `cn` locale 內容外，不要在繁體中文回覆或文件中使用簡體中文。

## 執行步驟
1. 在產出任何內容前，確認是否包含繁體中文以外的非技術性文字。
2. 若新增 UI 字串，搜尋既有 locale key，優先沿用既有詞彙與語氣。
3. 若發現 `tw`、`cn`、`en`、`ja` 有缺漏或語意不一致，除非使用者明確要求只改單語，否則一併修正。

## 範例
- **正確**：已修正備料台的市場價格說明，並同步四個語系。
- **錯誤**：请确认这个改动是否可以。(使用簡體)
- **錯誤**：Please approve the implementation plan. (除非是純技術輸出，否則不應全英文)

## 注意事項
- 本技能具有高優先級。若其他文件使用英文描述舊規格，請理解內容後用繁體中文向使用者說明。
